# File storage

Images uploaded in LT ODM are stored as **files on the web server**, not in the database. The database stores only each file's address (a short URL with a random file name).

## Where

One root folder, set by `Files:Root` (environment variable `Files__Root`). Default: `<API folder>\App_Data\uploads`. On servers set it to a folder **outside the site**, e.g. `D:\LTODM\uploads`, so a release never overwrites or deletes it.

| Subfolder | What | Uploaded from | Served at (signed-in users only) | Referenced in the database by |
|---|---|---|---|---|
| `style-library\` | Style sketches and photos, colorway images, BOM line images, **AI renders** | Styles (style, colorway and BOM line forms); AI Studio > Style render | `/api/v1/styles/images/{name}` | `style.Style.SketchUrl`, `style.Style.ImageUrl`, `style.Colorway.ImageUrl`, `style.BomLine.ImageUrl`, `style.AiRender.ImageUrl` |
| `concept-inspiration\` | Concept Studio inspiration board images | Concept Studio | `/api/v1/concept-studio/images/{name}` | The TMS concept record's `inspiration_images` (JSON list of addresses) |
| `sbu-products\` | SBU product photos | SBU Products | `/api/v1/sbu-products/images/{name}` | The TMS SBU product's image field |

Example: a style photo saved as `D:\LTODM\uploads\style-library\3f2a…9c1e.jpg` is stored in `style.Style.ImageUrl` as `/api/v1/styles/images/3f2a…9c1e.jpg`.

Subfolders are created on the first upload.

## Compression

Every image is made smaller **on the server** before it is written, whether it was uploaded or generated by AI (`ImageOptimizer`, using SkiaSharp):

| Step | What happens |
|---|---|
| Size limit | Longest side at most **1600 px** in `style-library` (style page, proposals, printing; sketch details stay readable), **1200 px** in `concept-inspiration`, **800 px** in `sbu-products`. Smaller images are never enlarged |
| Upright | Phone photos that record their rotation separately are turned the right way up |
| Format | Photos are saved as **JPEG quality 82** (no visible loss at these sizes). Sketches and graphics (transparency or flat colours) stay **PNG** when that is not more than 30% bigger than the JPEG, so lines stay sharp |
| Metadata | Camera details and GPS position are removed |
| Already small | A file that is already within the limit and would not get smaller is kept as uploaded |

The browser also resizes before uploading (same limits) so uploads are quick; the server step covers anything that skips the browser (AI renders, other clients). A file that cannot be decoded is refused with *"This image could not be read"*.

Typical stored sizes: a 1600 x 1067 photo or AI render **250-400 KB** (a phone photo of 3-8 MB, or a 1-2 MB AI render, before), a 1600 px line sketch **30-150 KB**, an 800 px product photo **60-120 KB**. Images stored before this change are not re-compressed.

## File names and checks

- Names are **32 random hexadecimal characters + extension** (`.jpg`, `.png`, `.gif`, `.webp`). Users cannot choose or guess them; the original file name is not kept.
- The type is checked from the **file content** (not the name): only JPEG, PNG, GIF and WebP are accepted; at most **10 MB** each.
- AI renders are checked the same way before they are saved (PNG, JPEG or WebP).
- When served, files get `X-Content-Type-Options: nosniff` and a `Content-Security-Policy` that stops a browser running them as anything but an image. Requests for names that do not match the pattern are refused.
- The browser loads images with the user's sign-in token; nothing is reachable without signing in, and the folder is not under the web root.

## What is *not* stored as a file

- **Import workbooks** (Settings > Import): read in memory and copied into the `staging` tables; the `.xlsx` itself is not kept.
- **Images given as `https://` addresses** in an imported workbook (Sketch / Image columns): only the address is stored; the app does not download them.
- **Translation corrections** (Settings > Translations): one JSON file, `overrides.json`, plus its `history\` folder, in `Translations:OverridesFolder` (default `<API folder>\App_Data\i18n`; on servers e.g. `D:\LTODM\i18n`, outside the site). Back it up with the uploads. Uploaded translation workbooks are read in memory and not kept.
- **API keys** of AI connections: in the database, encrypted (see `DataProtection:KeysFolder` in [Configuration](04-configuration.md)).

## Deleting

Removing an image from a style, colorway, BOM line, concept or product **does not delete the file**, because another record may still use it (a reused style keeps its images, a saved concept keeps its board). Deleting an AI render removes its record; the file stays. Unused files are not cleaned up automatically yet: to free space, compare the folder against the addresses in the columns above.

## Permissions, backup and moving

- The app-pool account needs **Modify** on the root folder. Users never access it directly.
- **Back it up together with the database** (same schedule). A database restored without the files shows broken images; files without the database are orphaned.
- To move the folder: stop the site, copy the folder with its subfolders, change `Files:Root`, start the site. The database addresses do not contain the folder path, so nothing else changes.
- Size: plan for about **0.4 MB per image** at most (see [Compression](#compression)); 10,000 style images need roughly 4 GB.
